# Project Dashboard - API + Microsoft Fabric + Power BI

[Versão em português](README.md)

Pipeline that pulls data from a project-management tool through an API, processes it in Microsoft Fabric (bronze, silver and gold) and delivers a Direct Lake semantic model with a 3-page executive Power BI report. The model and the report are generated from code and published by a notebook.

It follows the [Ideas Dashboard](https://github.com/GuilhermeRostirolla/painel-ideias-powerbi). There the data came from SQL Server; here it comes from an API shaped like AEVO's Central de Iniciativas (portfolios, projects, tasks and stage movements), so ingestion has to deal with tokens, pagination, incremental loads and rate limits.

![Portfolio](docs/img/portfolio.png)

## Data

The data is fictitious. Project and people-performance data is sensitive, so I built a simulated API that behaves like a real one (token, pagination, incremental filter and the occasional 429). Behind it, a Python simulator runs each task through AEVO's kanban (Backlog, A fazer, Fazendo, Impedido, Em revisão, Concluído, Arquivada), with impediments, rework and archiving. Projects carry AEVO's portfolio stage, status, traffic light, origin (idea, startup or direct), manager and budget.

Scenario on 2026-09-30: 8 portfolios, 122 projects, 147 people, 4,467 tasks and 24,424 movements since Jan/2024; 12 projects late and R$ 10.3M in budget.

## Architecture

- **Bronze (`nb_01`)**: stores each API page as received, with a watermark per resource that only moves forward when every resource was written. Retries on 429/5xx using `Retry-After`. Token in Azure Key Vault.
- **Silver (`nb_02`)**: fixed schema per resource, cleaned text and dates, one row per record. Rule breakers go to `silver_rejeitados` with the reason.
- **Gold (`nb_03`)**: star schema; cycle time, impeded time and rework come from the movement history. Everything is measured against the reference date stored in the data.
- **Semantic model**: Direct Lake, 7 tables, 54 measures and one RLS role per portfolio (8), generated as TMDL by `tools/gerar_modelo.py`.
- **Report**: PBIR generated by `tools/gerar_relatorio.py`. Three pages (Portfolio, Projects and tasks, Gantt schedule) in a dark executive layout: card backgrounds are rendered from HTML and the transparent visuals sit on the same grid (`tools/design/`).
- **Publishing (`nb_04`)**: creates the model and report through the Fabric REST API, checks every measure in DAX against an independent SQL calculation and queries the model as each RLS role.

## Tests

`pytest` covers the simulator, API, notebooks, semantic model and report. `pytest -m pipeline` runs the Fabric notebooks on local Spark. An incremental load with 30% of API calls failing produced the same gold as a full load.

## Running it

```bash
pip install -r requirements-dev.txt
pytest
python tools/rodar_local.py --limpar
```

In Fabric, create a lakehouse named `lh_projetos` and run in any notebook:

```python
import requests; exec(requests.get("https://raw.githubusercontent.com/GuilhermeRostirolla/painel-projetos-fabric/main/tools/instalar_no_fabric.py").text)
```

Then run `nb_00_orquestrador` and `nb_04_publicar_modelo`. Details in the [Portuguese README](README.md).
